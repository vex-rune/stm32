### 介绍

MISRA C 是一套针对 C 编程语言的软件开发指南，由 MISRA 联盟制定。其目的是在嵌入式系统（特别是使用 ISO C / C90 / C99 编程的系统）的背景下，促进代码的安全性、可移植性和可靠性。

尽管最初专为汽车行业制定，MISRA C 如今已演变为一种被广泛接受的最佳实践模型，被汽车、航空航天、电信、医疗设备、国防、铁路等多个领域的领先开发者所采用。

### 分类

每条指南被划分为强制（MISRA C:2012 中新增）、必需（Required）或建议（Advisory）三个等级。

- **强制指南** 必须始终遵循
- **必需指南** 必须遵循，除非有正式的偏差记录
- **建议指南** 被视为良好实践，但其遵循性要求相对宽松

### 合规性

对于一段软件，若要声明符合 MISRA C 指南，则必须满足所有强制性规则，并且所有必需规则和指令要么被遵循，要么有正式的偏差记录。

许多 MISRA C 规则可被视为指导原则，因为在某些条件下，软件工程师可以偏离这些规则，但仍被视为符合标准。偏差必须记录在代码中或单独的文件中。此外，必须提供证据证明软件工程师已考虑系统的安全性，并且偏离该规则不会产生负面影响。偏差的要求还包括：

- 偏离的规则编号。
- 偏离的理由。

### 代码

LibDriver 遵循带偏差的 MISRA 标准。LibDriver 遵循所有强制性指南和大多数必需指南，偏差情况如表 1 所示。

<div align=center> 表 1. 指南偏差 </div>

| 指南 | 描述 | 状态 | 解释 | 严重程度 |
| --------- | ------------------------------------------------------------ | ------------ | ------------------------------------------------------------ | -------- |
| 10.1      | 操作数不应具有不恰当的本质类型。（\|、&、~、<<、>>） | 不兼容 | 嵌入式驱动需要使用此方法来设置或清除某些位，驱动保证操作的安全性。 | 极低 |
| 10.3      | 表达式的值不应被赋给具有更窄本质类型或不同本质类型类别的对象。（<<、>>） | 不兼容 | 嵌入式驱动需要使用此方法来设置或清除某些位，驱动保证操作的安全性。 | 极低 |
| 10.4      | 执行通常算术转换的运算符的两个操作数应具有相同的本质类型类别。（\|、&、<<、>>） | 不兼容 | 嵌入式驱动需要使用此方法来设置或清除某些位，驱动保证操作的安全性。 | 极低 |
| 10.8      | 复合表达式的值不应被转换为不同的本质类型类别或更宽的本质类型。 | 不兼容 | 我们使用此函数来转换驱动数据，驱动保证操作的安全性。 | 极低 |
